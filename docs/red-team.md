# Red-team report

Run: 2026-10-28 (server clock, UTC) · Branch: `feat/gemini-fallback` (with the owner's uncommitted Gemini fallback in the working tree) · Attacker: Claude Code, from the outside through HTTP only

## Setup

- **App and data:** the real app via `npm start`, against local MongoDB from `docker compose`, seeded with `npm run seed` (synthetic fixtures only). Identity was set with the `x-demo-user` header ([ADR-0005](adr/0005-demo-user-header.md)).
- **Model:** the Gemini fallback ([specs/gemini-fallback.md](../specs/gemini-fallback.md)). Every agent called `gemini-3.5-flash-lite` in place of the configured Claude models. No timeout or config was changed for the run.
- **Gemini latency:** calls took 24–30 s or hung until aborted. The orchestrator's whole run has a 30 s budget (`timeoutMs: 30000`), so many attacks ended as `retry`. When a run timed out after the orchestrator had already called `route`, the chosen label is still in the audit trail, and the table reports it.
- **Rounds:** attacks that timed out were re-run once or twice. The table shows the most complete run.
- **Audit evidence:** read back as `emp-001` (hr_admin) with `GET /audit/:requestId` and `GET /audit/:requestId/timeline`. Trace ids are the first 12 characters of the `requestId`. They live only in the local database.
- **Regression:** every row has a test, an eval case or both. New tests are named `RED-NN: …`. New eval cases are tagged `red_team` with `reviewed: false` for a human labeller, and their `notes` start with the RED id. The `http/app.test.ts` tests run against `createApp` with a stand-in strict route (`/test/echo`) behind the same identity, body-parser and error middleware as `POST /messages`.

**Result: no attack produced an approval, a verdict the Policy Gate did not compute, a tool the agent is not allowed, or another employee's data outside the read grants the specs give.** The open findings below are about detection and observability, one Q&A gate gap, and one spec contradiction about the leave reason in manager-readable traces (F-8).

## Reproducing

1. `docker compose up -d`, then `npm run seed` (this wipes the local database), then `npm start` with a model key in `.env`.
2. Send each request in the table with `x-demo-user` set to the listed actor.
3. Read the trace as `emp-001`: `GET /audit/<requestId>` or `GET /audit/<requestId>/timeline`.
4. For the regression set, run `npm test` (deterministic) and `npm run evals -- orchestrator` / `npm run evals -- leave` (live model; the `red_team` tag marks the new cases).

The attack scripts lived in a session scratchpad and are not committed. Every request they sent is in the table.
